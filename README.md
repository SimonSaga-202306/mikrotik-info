## 本轮新增的长期规则

1. **深搜整个仓库**：包含档案、原始批次、代码、历史、Office工作表/段落及隐藏资料；明确未解析和未核实范围，不用抽样冒充全量。
2. **发现的信息必须带来源**：在相关MD/字段旁写URL或本地文件位置、对应事实、检索/记录日期、来源等级；找不到证据就标“待补证”，不猜。
3. **结构准确、清晰、可读**：入口、主数据、生成物、原始材料、历史分层；整理目录不构成客户重排授权。
4. **用户要求统一记录**：所有可恢复用户要求集中在一个[总账MD](docs/requirements/用户要求总账.md)，每轮带消息时间（能恢复的精度）和真实记录时间。旧摘要不是用户原文，提交时间不是发言时间，未知不得补造。
5. **README持续更新并核验**：每轮写明进度、未完成事项、下一位编号与规则变更；按历史要求用 `grep -c` 检查实际写入。

## 不变的操作边界

- 存量编号、CSV物理顺序不动；**前49位仅内容可编辑（2026-09-28 用户授权），位置/顺序仍冻结**；第37轮的一次性尾部重排许可已使用完。
- 不擅改评级规则。Bechtle A103保级是个案；A080风险已知悉不代表证书有效。
- 跟进线下维护，用户有实际回复并要求时才入库；不主动设计或追问跟进流程。
- A 类档案的加厚内容（维度/证据/3 步计划）只写进 `batch/A类加厚_*.json`，由 `scripts/make_profiles.py` 渲染进档案；不要手改 `profile/`，否则下次重建会丢失。
- 公共邮箱≠可投递、在职或有采购权；猜测邮箱、遮罩邮箱、网站服务商邮箱不能算找到。
- 历史模板卖点/首触邮件/场景分类是内部分析，不是已核实的客户事实或逐SKU实测。

依赖：Python 3.10+、Git、`openpyxl`（现有xlsx管道依赖）；审计/测试不会启动网络服务。

```bash
python3 scripts/audit_repository.py --date 2026-09-27
python3 -m unittest discover -s tests -v
git -c core.whitespace=blank-at-eol,blank-at-eof,space-before-tab,cr-at-eol diff --check
```

审计脚本不联网、不重评级、不修改客户；它扫描并报告缺口，不能替代网页核验。重建档案/导出前的额外保护见 [AGENT-README](AGENT-README.md)。
